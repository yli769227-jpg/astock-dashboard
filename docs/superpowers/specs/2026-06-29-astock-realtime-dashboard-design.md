# A 股全市场实时盯盘网页 · 设计文档（Spec）

- 日期：2026-06-29
- 状态：已与用户逐段确认，待 review
- 形态：本地可跑 + 内网可分享给同事的实时盯盘网页（第一版纯只读 + 轻下钻）

---

## 0. 一句话定义

> 一个**全市场扫描型**的 A 股实时盯盘网页：东方财富免费接口 → Node 后端（主动拉取 + 内存缓存 + 懒加载 + 失败降级）→ Vue 3 + Vite + ECharts 前端（顶部概览 / 涨跌幅榜 / 板块异动 三面板 + 板块下钻成分股 + 个股分时卡片，红涨绿跌 + 变化闪烁，3 秒刷新）。可本地跑、可内网分享给同事。

核心目标是「发现」而非「跟踪」——看全市场此刻哪里有异动 / 机会，不是盯固定几只自选股。

---

## 1. 关键决策记录（含理由）

| 维度 | 决策 | 理由（第一性原理） |
|------|------|------|
| 盯盘场景 | 全市场扫描（榜单/板块异动） | 用户要「发现机会」，不是跟踪持仓 |
| 数据源 | 东方财富免费公开接口 | 扫描场景只需榜单级数据，3 秒级延迟足够；零成本、马上能跑；榜单类数据它免费就给全 |
| 交付形态 | 本地网页，可内网部署分享 | 多面板 + 颜色闪烁 + 下钻，网页表达力最强；不写死 localhost，便于同事访问 |
| 第一版面板 | 顶部概览 + 涨跌幅榜 + 板块异动 | 三者都是真·实时、信息密度高、接口直接能取；龙虎榜是盘后数据故不进实时区 |
| 交互深度 | 轻下钻（板块→成分股、个股→分时卡片） | 信息立体但不做成全功能客户端 |
| 技术栈 | Node 后端 + Vue 3 + Vite + ECharts | 用户 Node 生态熟；榜单密集表格 + 频繁局部刷新适配 Vue 响应式；ECharts 是国内看盘图表事实标准 |
| 刷新频率 | 常驻数据 3 秒、板块 5 秒、非交易时段 30 秒 | 盯盘够用又不触发东方财富风控 |
| 数据持久化 | 无数据库，仅内存缓存 | 盯盘只关心「此刻」，不留历史（YAGNI） |

## 2. 整体架构与数据流

```
┌─────────────────────────────────────────────┐
│  浏览器（同事/你）  Vue 3 + Vite + ECharts     │
│   顶部概览条 | 涨跌幅榜 | 板块异动 | 下钻卡片    │
└───────────────┬─────────────────────────────┘
                │ 只调我们自己的后端（同源，无跨域）
                │ 每 3 秒轮询 /api/*
┌───────────────▼─────────────────────────────┐
│  Node 后端（Express 或 Fastify）               │
│  ┌─────────────┐  ┌──────────────────────┐  │
│  │ 路由层 /api  │→ │ 缓存层（内存 + TTL）    │  │
│  └─────────────┘  └─────────┬────────────┘  │
│                             │ 缓存未命中才回源  │
│                   ┌─────────▼────────────┐    │
│                   │ 东方财富抓取 + 清洗适配层 │    │
│                   └─────────┬────────────┘    │
└─────────────────────────────┼────────────────┘
                              │ 3 秒一轮主动拉取
                    ┌─────────▼──────────┐
                    │  东方财富免费行情接口  │
                    └────────────────────┘
```

**三条核心设计原则：**

1. **后端主动拉、客户端被动取**：后端起定时器每 3 秒主动抓东方财富全市场数据写进内存缓存；所有浏览器客户端只读这份缓存。**无论 1 个还是 50 个同事在看，对东方财富的请求量恒定不变**——这是「可分享给同事不被封 IP」需求的核心约束。
2. **后端做代理，前端永不直连东方财富**：解决跨域 + 隐藏数据源 + 统一字段清洗（东方财富返回 `f12/f14/f3` 编号字段，后端翻译成 `code/name/changePct` 再给前端）。
3. **内存缓存即可，第一版不引入数据库**：盯盘只关心此刻，历史不留存。

**数据流一句话**：东方财富 →(3s 定时)→ 后端清洗写缓存 →(浏览器 3s 轮询)→ 前端渲染。

## 3. 后端数据层

### 3.1 对接的东方财富接口

| 面板 | 数据内容 | 拉取频率 | 说明 |
|------|---------|---------|------|
| 顶部概览 | 上证/深证/创业板指 + 涨跌家数 + 北向资金 | 3 秒 | 数据量小，最实时 |
| 涨跌幅榜 | 全市场沪深京 A 股列表（带排序参数） | 3 秒 | 一次拉全市场，后端内存排序切榜 |
| 板块异动 | 行业板块 + 概念板块列表 | 5 秒 | 板块变化较慢，拉稀一点省请求 |
| 下钻·板块成分股 | 指定板块成分股列表 | 按需 5 秒 | 仅当有人展开某板块时拉，且缓存 |
| 下钻·个股分时 | 个股分时图数据 | 按需 3 秒 | 仅当有人打开某股卡片时拉 |

> 注：具体接口 URL / 参数在实施阶段以实际抓包为准，并存档真实返回样本作为测试 fixture（见 §6）。

### 3.2 缓存与节流策略（核心）

- **常驻拉取**（概览 / 涨跌幅榜 / 板块）：后端启动即开定时器，无人看也拉，保证客户端一连上就有最新数据、零等待。
- **按需拉取**（成分股 / 分时）：**懒加载**——只有至少一个客户端打开某板块 / 某股时，后端才把它加进「活跃拉取清单」；最后一个客户端关闭后，**60 秒无人问津就停止拉取**该项，避免定时器无限膨胀。
- **缓存 TTL = 拉取间隔**：前端来取直接给内存里最新那份，永不阻塞等回源。
- **回源失败降级**：某次抓取失败 → **保留上一份缓存继续供给** + 给该数据打 `stale: true` 标记，前端顶部显示「⚠️ 数据更新中断，展示 X 秒前快照」，而非整界面崩溃或清空。

### 3.3 对外接口（前端只见这套干净接口）

```
GET /api/overview                    → 指数 + 涨跌家数 + 北向
GET /api/ranking?type=up&limit=50    → 涨跌幅榜（type: up/down/amplitude/turnover）
GET /api/sectors?type=industry       → 板块榜（industry/concept）
GET /api/sector/:code/stocks         → 某板块成分股（下钻，触发懒加载）
GET /api/stock/:code/timeline        → 某股分时（下钻，触发懒加载）
```

每个响应统一包裹元信息：`{ data, updatedAt, stale }`，前端据此渲染「更新心跳」和「stale 提示」。

### 3.4 关键路径日志（新代码必须有）

每个回源动作打日志，便于排查「为啥数据不动了」：

```
[东方财富] 拉取涨跌幅榜 OK 5012 条 耗时 312ms
[缓存] /api/ranking 命中
[降级] 板块接口失败，供给 8s 前快照
[告警] 字段 f3 缺失，疑似上游接口变更
[懒加载] 板块 BK0475 进入活跃清单（当前 2 个客户端）
```

## 4. 前端界面

### 4.1 整体布局（一屏看完，盯盘不滚屏）

```
┌──────────────────────────────────────────────────────────┐
│ 顶部概览条  上证 3021 +0.8% | 深证 … | 创业板 … |          │
│            涨1832/平210/跌2705 | 北向 +52亿 | ⏱03秒前更新  │ ← 常驻置顶
├────────────────────────────┬─────────────────────────────┤
│  涨跌幅榜（主区，左 60%）      │  板块异动（右 40%）            │
│  ┌─[涨幅][跌幅][振幅][换手]┐ │  ┌─[行业][概念]──────────┐  │
│  │ 排名 代码 名称 现价 涨跌% │ │  │ 板块名 涨跌% 领涨股      │  │
│  │  1  300xxx ▲ +12.3%  闪 │ │  │ 半导体 +3.2% …  ← 可点  │  │
│  │  2  60xxxx ▲ +11.8%     │ │  │ 白酒   +2.1% …          │  │
│  │  …（前 50，可切 tab）    │ │  │ …                       │  │
│  └────────────────────────┘ │  └────────────────────────┘  │
└────────────────────────────┴─────────────────────────────┘
        点板块行 → 右侧下方展开成分股榜
        点个股行 → 弹出分时图卡片（浮层）
```

### 4.2 组件拆分（单一职责、可独立测试）

| 组件 | 职责 | 依赖 |
|------|------|------|
| `OverviewBar` | 顶部概览条，渲染指数/涨跌家数/北向/更新时间 | `/api/overview` |
| `RankingTable` | 涨跌幅榜表格 + 4 个 tab 切换 | `/api/ranking` |
| `SectorPanel` | 板块榜 + 行业/概念切换 + 点击展开 | `/api/sectors` |
| `SectorStocks` | 板块成分股榜（下钻，SectorPanel 展开时挂载） | `/api/sector/:code/stocks` |
| `StockTimelineCard` | 个股分时图浮层卡片（ECharts） | `/api/stock/:code/timeline` |
| `usePolling`（组合式函数） | 统一的 3 秒轮询 + 页面隐藏暂停 + 出错重试 | 被上面各组件复用 |

### 4.3 盯盘视觉细节（看盘界面与普通表格的区别）

1. **红涨绿跌**——按 A 股习惯（**与欧美相反**），涨红跌绿，硬编码主题色。
2. **变化闪烁**——某票现价/涨跌幅刷新时与上一帧不同，单元格闪一下底色（涨闪红、跌闪绿），半秒淡出，让「在动的票」一眼可见。
3. **更新心跳**——顶部「⏱ 03 秒前更新」实时跳秒；一旦后端 stale，变黄字「⚠️ X 秒前快照」。
4. **页面隐藏暂停**——`usePolling` 监听 `visibilitychange`，切走时停止轮询，回来立刻拉一次。省后端、省东方财富请求。
5. **数字等宽**——价格/涨跌幅用等宽字体，跳动时不抖动。

### 4.4 第一版明确不做（YAGNI）

- ❌ 登录/账号体系（内网分享，开箱即用）
- ❌ K 线图（只做分时，K 线第二版）
- ❌ 自选/置顶（第二版）
- ❌ 移动端适配（先做桌面大屏）

## 5. 错误处理与健壮性

| 故障场景 | 处理方式 |
|---------|---------|
| 东方财富某接口单次失败 | 保留上一份缓存继续供给 + 标 `stale` + 日志 `[降级]`，界面不崩 |
| 东方财富改字段/返回结构变了 | 适配层「字段缺失即跳过该条」而非整批报错；打 `[告警] 字段 X 缺失` 日志 |
| 东方财富封 IP / 连续失败 | 后端指数退避（3s→6s→12s 最多 30s），顶部条「⚠️ 行情源连接异常，重试中」；恢复后自动回 3s |
| 前端某次轮询失败 | 静默重试，连续 3 次失败才在该面板显示「更新中断」，不打断其他面板 |
| 浏览器开太多 tab / 内存涨 | 页面隐藏即暂停轮询；分时卡片关闭即销毁 ECharts 实例 |
| 盘前/盘后/午休非交易时段 | 后端识别交易时段，非交易时段降到 30 秒一拉，顶部显示「🕐 非交易时段 / 已收盘」 |

## 6. 测试策略（完成 = 可验证的测试结论，输出 ✅/❌/⚠️）

1. **适配层单测（最关键）**——用**真实抓取存档的东方财富 JSON 样本**做 fixture，断言：编号字段→干净字段翻译正确、缺字段降级不抛错、排序切榜正确。这是最容易因上游变动而坏的地方，必须有测试兜底。
2. **缓存/懒加载逻辑单测**——断言：无客户端时不拉按需接口；有客户端时拉；最后一个客户端走后 60s 停拉；回源失败时供给旧快照且标 stale。
3. **接口契约测试**——`/api/*` 每个端点返回结构断言（前端依赖的字段都在）。
4. **前端组件测试**——`usePolling` 暂停/恢复/重试；红涨绿跌取色函数；闪烁触发逻辑。
5. **冒烟测试（交付前）**——真连东方财富跑起来，肉眼验证：榜单在动、颜色对、闪烁有、下钻能展开、分时图出得来、拔网线后 stale 提示出现。输出 ✅/❌/⚠️ 结论。

## 8. 合规与免责

- 数据来自东方财富免费公开接口，仅供盯盘参考，**不构成投资建议**。
- 接口为非官方授权使用，存在限频/封禁/字段变更风险，故架构上以「后端单点拉取 + 降级容错」缓解。
- 界面显著位置标注数据延迟与免责声明。
